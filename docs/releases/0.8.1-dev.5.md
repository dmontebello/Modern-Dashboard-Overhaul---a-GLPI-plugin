
# MDO 0.8.1-dev.5 — Kanban SQL GLPI 11 e visibilità Standalone

Data: 25 ottobre 2026. Branch Dev, Main invariato. La correzione è basata su log dell'utente GLPI 11.0.9. Lo stato dopo l'aggiornamento resta **NON COLLAUDATO LIVE**.

## Fix, cause e File modificati

**KANBAN-SQL-1054**: l'utente osservava "Unable to load tasks" e i log registravano `Unknown column 'DESC' in 'order clause' (1054)`, query ProjectTask con `ORDER BY \`DESC\``. Nel GLPI 11.0.9, `DBmysqlIterator::handleOrderClause()` riceve una stringa oppure un array di **espressioni**, non una mappa campo => direzione. Il vecchio codice MDO usava `['glpi_projecttasks.id' => 'DESC']`, da cui SQL errato.

- `src/TaskBoard.php`: correzione di entrambe le query candidate, project task e project chooser, con `['glpi_projecttasks.id DESC']` e `['glpi_projects.id DESC']`.
- `src/StandaloneTask.php`: stesso fix di `loadBoard()`, usando `[$table . '.id DESC']`.
- `front/tasks.php`: avviso amministrativo solo se Standalone è abilitato ma il profilo attuale non ha READMY/READALL. L'accesso diretto non autorizzato resta negato; nessuna concessione automatica.
- `tests/task_bootstrap.php`: aggiornato il double DB per rifiutare ORDER associativo e simulare il comportamento del generatore SQL GLPI 11; gestione amministrativa `config:UPDATE`.
- `tests/tasks_php.php` e `tests/standalone_php.php`: regressione sui tre ORDER e sull'avviso di permessi che non divulga dati.
- `setup.php`, `README.md`, `CHANGELOG.md`, `QA.md`, `docs/dev/STATUS.md`, documenti di sicurezza/integrità/staging e note tecniche aggiornati alla dev.5.
